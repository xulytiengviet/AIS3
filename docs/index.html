02 / Hardware specification

Chọn đúng ESP32-S3 trước khi nạp

04 / Cài đặt AIS3

Hướng dẫn từng bước

Quy trình chuẩn của repository AIS3 chia thành hai phần: fetch_model.sh chỉ tải/xác minh dữ liệu; deploy.sh kiểm tra, biên dịch rồi mới nạp Flash.

Linux: đảm bảo công cụ build C/C++, Python 3.12+, uv, arduino-cli, hf, shasum, esptool và quyền truy cập USB.

0/6 mục · Checklist chỉ lưu trong phiên trang hiện tại.

01

Clone source AIS3

Chạy trong Terminal/PowerShell (trong WSL2 nếu chọn Windows).

Git
git clone https://github.com/xulytiengviet/AIS3.git
cd AIS3
02

Cài công cụ cho hệ điều hành

Gói cần thiết: Python ≥3.12, Git, C compiler, Arduino CLI, uv, Hugging Face CLI (hf), esptool và shasum. Cài đặt trước khi chạy script.

Linux / ví dụ Ubuntu
sudo apt update
sudo apt install -y git build-essential python3 python3-pip python3-venv perl
python3 -m pip install --user uv huggingface_hub esptool
# Cài Arduino CLI từ https://arduino.github.io/arduino-cli/
# Đảm bảo các lệnh uv, hf, esptool, arduino-cli có trong PATH.

Nếu hệ điều hành chặn pip vào Python hệ thống, hãy dùng pipx hoặc môi trường ảo thay vì ép cài đặt.

03

Cài Espressif Arduino core và thư viện OLED

Arduino CLI
arduino-cli core update-index --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core install esp32:esp32@3.3.10 --additional-urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli lib install 'Adafruit SH110X@2.1.14' 'Adafruit GFX Library@1.12.6' 'Adafruit BusIO@1.17.4'

Thay đổi theo nút chọn mô hình ở phần 03. Script tải từ kho phát hành Hugging Face; không nạp thiết bị.

Đóng mọi Serial Monitor khác. Mở cổng dữ liệu, xác định tên cổng nếu script không tự dò được.

05 / OLED & nguồn điện

Đấu màn hình cho AIS3 N16R8

OLED đơn sắc 128×64 có thể chạy SH1106 hoặc SSD1306. Dùng nguồn 3,3V, cấp nguồn đúng chân và ngắt USB trước khi đi dây.

Pinout này đúng với firmware/esp32_tinystories/display.h và tài liệu các sketch AIS3; không được tự động áp vào Super Mini hoặc bo XiaoZhi. Với Super Mini, phải chọn GPIO có sẵn và sửa firmware theo pinout bo đó.

Tùy chọn điều khiển OLED trong AIS3: SH1106 (thường màn 1,3″), SSD1306 (thường màn 0,96″), địa chỉ phổ biến 0x3C hoặc 0x3D. Màn hình OLED ASCII mặc định có thể không hiển thị đầy đủ dấu tiếng Việt; ưu tiên USB Serial UTF-8.

07 / Tham chiếu ESP32-S3 Super Mini AI

Làm web AI cục bộ trên bo 4 MB

Dự án Ngducok/esp32s3-Super-mini-AI ↗ dùng mô hình Micro-Transformer riêng, không phải mô hình 28,9M của AIS3. Theo tài liệu tác giả: 118.784 tham số; 3 lớp, d=64, 4 attention heads; ring KV-cache 24,5 KB; độ trễ token đầu 15,5 ms và thông lượng bình quân khoảng 20 tok/s trên cấu hình đo. Các số liệu này chưa phải benchmark AIS3.

Sau khi nạp bản có SoftAP, kết nối Wi‑Fi ESP32-Local-AI bằng mật khẩu demo 12345678, mở http://192.168.4.1. Đây là địa chỉ của thiết bị gần bạn, không phải website AIS3; đổi mật khẩu mặc định nếu đưa demo vào môi trường có người khác.

Tài liệu Super Mini: README tiếng Việt · tài liệu firmware/benchmark. Không thực hiện các lệnh nạp Super Mini khi đang muốn giữ firmware AIS3 trên cùng bo.

08 / Vietnamese LLM · thực nghiệm

Huấn luyện TinyStories tiếng Việt đúng quy trình

Không chỉ thay file văn bản. Để tạo truyện tiếng Việt có dấu, cần dữ liệu UTF‑8 chuẩn, tokenizer nhất quán, checkpoint tương thích, huấn luyện trên máy tính, kiểm tra chất lượng, lượng tử hóa int4 rồi nạp model lên N16R8.

Luồng dữ liệu

Truyện UTF‑8 → NFC / lọc dữ liệu → tokenizer ByteLevel-BPE → train.bin + val.bin → Train/Fine-tune PLE trên GPU/CPU → checkpoint .pt → kiểm thử tiếng Việt → model.bin INT4 + golden → ESP32-S3

Ranh giới quan trọng: Model đã nạp dưới dạng model.bin 4-bit không phải checkpoint PyTorch để fine-tune trực tiếp. Fine-tune cần file runs/*.pt và đúng tokenizer, đúng kiến trúc. Nếu huấn luyện tokenizer mới cho tiếng Việt thì phải huấn luyện từ đầu hoặc xây dựng quy trình ánh xạ embedding; không được nạp checkpoint tiếng Anh với tokenizer mới.
Muốn fine-tune mà chưa có checkpoint gốc? Hãy tạo checkpoint tiếng Anh tương thích bằng quy trình nghiên cứu của AIS3: uv run python -m research.tinystories.prepare --vocab 32768, sau đó uv run python -m research.tinystories.train --arm ple --vocab 32768 --d-model 96 --n-layers 6 --n-heads 4 --ple-dim 128 --target-core 559000 --steps 3000 --tag en-base --seed 0. Quá trình này cần dữ liệu và thời gian huấn luyện trên PC; checkpoint sinh ra là runs/ple-en-base-s0.pt.
Đề xuất để sinh tiếng Việt: huấn luyện tokenizer ByteLevel BPE mới từ corpus tiếng Việt, sau đó train PLE từ đầu. Đây là retraining, không phải fine-tune từ checkpoint gốc.
01

Chuẩn bị corpus truyện tiếng Việt

Tạo tệp data/vi_stories.txt có các câu chuyện tiếng Việt được phép sử dụng, cách nhau bằng dòng trống. Giữ dấu tiếng Việt, không chuyển sang ASCII. Chia train/validation theo truyện, không trộn cùng một truyện ở hai tập.

Ví dụ corpus · UTF‑8
Ngày xửa ngày xưa, ở một ngôi làng nhỏ có một bạn thỏ tên là Mây. Mây thích giúp đỡ những người bạn trong rừng.

Một buổi sáng, cậu bé An nhặt được một hạt giống. Cậu gieo hạt, tưới nước và kiên nhẫn đợi cây lớn.

Ví dụ chỉ để minh họa định dạng, không đủ dữ liệu để tạo mô hình mạch lạc. Thu thập nhiều truyện đa dạng, có bản quyền/giấy phép rõ ràng và loại bỏ dữ liệu cá nhân.

02

Chuẩn bị dữ liệu token

Dùng script research/tinystories/prepare_vi.py (được bổ sung trong AIS3) để chuẩn hóa NFC, tách truyện, lưu tokenizer, train.bin và val.bin tách biệt với corpus tiếng Anh.

Python · data preparation
uv sync
uv run python -m research.tinystories.prepare_vi \
  --input data/vi_stories.txt --vocab 32768
03

Huấn luyện/checkpoint

Chạy trên PC có GPU là tốt nhất. Cấu hình minh họa nhắm tới PLE N16R8, dung lượng model xuất ra còn phải kiểm tra với vùng Flash 15.597.568 byte. Khởi đầu nhỏ để thử pipeline rồi tăng số bước và dữ liệu.

Python · train PLE
uv run python -m research.tinystories.train_vi \
  --data-dir data/vi_tinystories/vocab-32768 \
  --steps 3000 --tag vi-demo
Cấu hình demo không bảo đảm tiếng Việt mạch lạc. Đánh giá bằng validation perplexity, kiểm tra thủ công tính nhất quán truyện, không lấy số tok/s tiếng Anh làm tốc độ đã đo của model tiếng Việt.
04

Thử sinh văn bản trước khi nạp

Host sample
uv run python -m research.tinystories.sample \
  --run runs/ple-vi-demo-s0.pt \
  --tokenizer data/vi_tinystories/vocab-32768/tokenizer.json \
  --prompt "Ngày xửa ngày xưa" --tokens 120
05

Export int4 & nạp N16R8

Exporter kiểm tra SHA-256 của tokenizer, tạo tệp model và golden. Thay prompt firmware từ ID cố định tiếng Anh bằng ID sinh từ tokenizer tiếng Việt; xuất Serial theo luồng byte UTF‑8 để không làm hỏng dấu.

Export + flash
uv run python -m research.tinystories.export ple-vi-demo-s0 \
  --tokenizer data/vi_tinystories/vocab-32768/tokenizer.json \
  --out-dir artifacts/vi_tinystories
ARTIFACTS=artifacts/vi_tinystories \
TINYSTORIES_PROMPT="Ngày xửa ngày xưa" \
scripts/deploy.sh tinystories

Một mô hình tiếng Việt mới chưa được đo/kiểm chứng sẵn trên board. Cần xác minh kích thước phân vùng, RAM thực tế, kiểm thử C golden và kết quả thiết bị. Màn OLED ký tự ASCII mặc định không hiển thị đủ dấu, nên đọc văn bản qua Serial UTF‑8.

09 / XiaoZhi Vietnamese DIY

Làm trợ lý AI giọng nói tiếng Việt

Dựa trên Ngthhoang/xiaozhi-vn-ricky0611 ↗ (nhánh develop_vn): firmware trợ lý giọng nói với ESP-IDF, I²S audio, Wi‑Fi, biểu cảm OLED/LCD và điều khiển IoT. Phần AI lớn thường thông qua backend, nên không đồng nhất với mô hình TinyStories chạy hoàn toàn offline.

Không cấp loa công suất trực tiếp từ GPIO hoặc nối các chân nguồn khi chưa kiểm tra sơ đồ. Không có một bảng GPIO chung an toàn cho mọi bo XiaoZhi/Super Mini. Xem custom-board.md và sơ đồ DIY trong README trước khi đấu dây.
01

Chọn bo phù hợp

Đối với người mới, ưu tiên bo có sẵn mic, DAC/amp, loa và firmware hỗ trợ. Tự lắp rời: xác định BCLK/WS/DIN cho micro và BCLK/WS/DOUT cho amplifier I²S, nguồn và GPIO nút, theo đúng board profile.

02

Cài ESP-IDF và build mã nguồn

Yêu cầu ESP-IDF v5.4+ theo README tham chiếu. Cài ESP-IDF theo hướng dẫn Espressif, mở terminal có sẵn idf.py rồi chạy:

XiaoZhi · ESP-IDF
git clone --branch develop_vn https://github.com/Ngthhoang/xiaozhi-vn-ricky0611.git
cd xiaozhi-vn-ricky0611
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
idf.py -p /dev/ttyACM0 flash monitor

Chọn chính xác model board trong menuconfig trước khi build. Thay cổng mẫu bằng COMx trên Windows hoặc /dev/ttyACM* trên Linux. Nếu thay đổi target/cấu hình cũ, cân nhắc idf.py fullclean trước khi build.

03

Hoặc nạp firmware đã build qua Web Flasher

Chỉ chọn bản firmware được xác minh dành đúng bo, Flash/PSRAM và sơ đồ GPIO. Web Flasher được README XiaoZhi giới thiệu ↗. Chrome/Edge hỗ trợ Web Serial trên một số hệ điều hành; tùy trình duyệt cần quyền USB.

04

Thiết lập Wi‑Fi và ghép thiết bị

Sau khi nạp, quan sát màn hình/log, cấu hình Wi‑Fi nhà bằng portal mà firmware cung cấp; khi firmware phát mã kích hoạt, ghép qua dịch vụ XiaoZhi tương ứng, rồi kiểm tra trạng thái xác nhận kết nối. Không nhập mã từ một hệ thống vào hệ thống khác nếu chưa được hỗ trợ.

05

Kiểm thử mic, loa và ngôn ngữ

Thử nút đánh thức/wake word theo cấu hình firmware, nói một câu tiếng Việt ngắn, xác nhận ASR → LLM → TTS trả lời. Nếu không có tiếng, kiểm tra nguồn, gain, dây I²S và profile codec. Kiểm thử ngắt kết nối để biết hệ thống có fallback hợp lý hay không.

Hướng kết hợp AIS3 + XiaoZhi (nghiên cứu): dùng AIS3 cho sinh truyện đơn giản offline, XiaoZhi cho lớp nhập/xuất giọng nói; thiết kế gateway giữa hai tiến trình/thiết bị hoặc giảm kích thước mô hình. Chưa có firmware tích hợp cả hai được xác nhận trong AIS3, nên không coi hướng này là đã cài được ngay.
10 / Sự cố thường gặp

Đối chiếu lỗi và hướng xử lý

Không tìm thấy cổng USB / COM / tty

Đổi cáp USB dữ liệu; thử BOOT/RESET theo hướng dẫn bo; đóng chương trình đang giữ cổng. Linux cần quyền udev/dialout phù hợp; Windows WSL2 cần USB passthrough qua usbipd. Kiểm tra arduino-cli board list.

missing artifact, lỗi SHA-256 hoặc tải mô hình không đủ

Kiểm tra Internet, cài Hugging Face CLI và chạy lại scripts/fetch_model.sh <model>. Không bỏ qua bước so hash/metadata và không đổi tên tệp tùy tiện.

model partition not found, bad model magic

Nạp lại đúng firmware và đúng phân vùng N16R8. Không trộn model Fly với TinyStories/Barista, không ghi model vào offset khác. Script deploy làm đúng thứ tự: compile → model → firmware.

Thiếu PSRAM hoặc FATAL: required PSRAM allocation failed

Đối chiếu board thực tế có 8 MB PSRAM, cấu hình PSRAM=opi và chế độ Flash 16 MB. Board Super Mini 4 MB/không PSRAM không đáp ứng yêu cầu mô hình AIS3 lớn.

OLED trắng, nhiễu hoặc không hiển thị

Đối chiếu SH1106/SSD1306 và I²C address 0x3C/0x3D, nguồn 3V3, SDA/SCL. Nếu đang dùng Super Mini, không áp sơ đồ chân 18/46 máy móc.

Văn bản tiếng Việt bị lỗi dấu

Kiểm tra corpus UTF‑8 NFC, tokenizer đúng với checkpoint, thử trên host trước. Cũ hơn: bộ sinh header có thể làm vỡ một ký tự UTF‑8 khi giải mã từng token lẻ; dùng bộ xuất raw ByteLevel bytes. OLED ASCII mặc định không có glyph tiếng Việt.

Fine-tune báo tokenizer mismatch

Đây là kiểm tra an toàn: phải dùng đúng tokenizer.json gắn với checkpoint bằng SHA-256. Nếu muốn tokenizer Việt mới, huấn luyện lại từ đầu, không cưỡng ép bỏ qua guard.

XiaoZhi không phản hồi giọng nói

Kiểm tra Wi‑Fi, máy chủ/activation, mic, amp I²S, nguồn và board profile. Việc ESP32 kết nối Wi‑Fi không xác nhận rằng ASR, TTS và LLM đều hoạt động; kiểm tra log của từng khâu.
